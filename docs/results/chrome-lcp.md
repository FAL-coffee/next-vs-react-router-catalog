# Chrome での実測（デプロイ済みサイト、2026-10-05）

Vercel にデプロイした両サイトを Chrome で計測。同じ画面サイズで各 5 回測った中央値。
初回表示は LCP（画面内の主要コンテンツが表示されるまでの時間）で比較。
制限環境は下り 1.6 Mbps・追加レイテンシ 150 ms・CPU 4 倍スローダウンの設定。実機スマートフォンの結果ではない。

| 計測項目 | Next.js | TanStack Router SPA |
| --- | --- | --- |
| 通常：初回表示 | 536 ms | 388 ms |
| 通常：キャッシュあり再読込 | 400 ms | 236 ms |
| 制限環境：初回表示 | 1,084 ms | 1,748 ms |
| 制限環境：キャッシュあり再読込 | 588 ms | 756 ms |
| 通常：クイックビュー表示 | 395 ms | 196 ms |
| 制限環境：クイックビュー表示 | 397 ms | 196 ms |

初回の転送量:

| | Next.js | SPA |
| --- | --- | --- |
| JavaScript | 149.4 kB | 98.1 kB |
| 商品画像 | 18.8 kB | 84.0 kB |
| 合計（先読み込み） | 202.4 kB | 196.3 kB |

所見:

- Next.js: HTML に商品情報があり、画像も最適化されている。制限環境での初回表示に有利だったと考えられる
- SPA: JavaScript は軽めだが、画像は元の PNG。画像最適化で改善できる余地がある
- クイックビュー: Next.js は同じ商品を開き直しても追加の RSC 通信が発生する。SPA には対応する商品データ通信が見られなかった
- クイックビューは読み込み後に同じ商品を 5 回開閉した結果。制限環境での最初の 1 回は Next.js 639 ms、SPA 208 ms
- 通常環境の SPA 初回表示には 360〜1,388 ms のばらつきがあった
- 実利用の INP や予約処理は未計測

画像・キャッシュ・データ取得方式の差も含むので、フレームワーク全般の優劣とは言えない。
